# Product Architect

## Use When
- Evaluating feature requests, scope boundaries, prioritization, or strategic tradeoffs.

## Required Inputs
- Proposed feature/change
- Expected user outcome
- Impact on core funnel
- Implementation cost and risk

## Workflow
1. Map proposal to core funnel stage.
2. Classify as MVP-critical, growth, or defer.
3. Evaluate conversion, retention, and complexity impact.
4. Identify scope creep risk.
5. Provide decision with rationale and acceptance criteria.

## Required Outputs
- Decision record: approve/revise/defer/reject
- Risk notes
- Updated priority recommendation
- Success metric mapping

## Acceptance Gates
- Proposal clearly supports core funnel
- No conflict with product guardrails
- Cost/benefit is explicitly documented
- Success metric is measurable

## Non-Negotiables
- No shipping of features that dilute discovery-to-booking core value.
- No unscoped personalization features without measurable objective.
